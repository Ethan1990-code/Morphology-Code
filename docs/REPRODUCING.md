# Reproduction guide

## Two different uses

1. **Quick figure rebuild:** restore the supplied frozen result snapshots and run the figure script. This recreates plots from existing results; it is not a raw-data replication.
2. **Raw-data rerun:** obtain the exact public inputs, run the steps below in a separate fresh clone, and compare newly generated results with `reference_results/`. Do not run the restore helper in that clone.

Dated directory names identify the actual analysis branches used in the manuscript. They are retained to keep imports and provenance unambiguous. Scripts write generated results beside their analysis code; these outputs are ignored by Git. Run commands from the repository root. Long analyses require substantial memory and time; this release does not include a tested universal resource estimate or a one-command raw-data pipeline.

## Dependency order

The EUOS historical exclusion set uses the JUMP, EveBio and cardiac identities. Complete the JUMP preparation and cardiac precursor steps before EUOS intake. These dependencies cannot be replaced with empty files without changing the study.

### JUMP preparation and comparison

Place the four inputs specified in [DATA_SOURCES.md](DATA_SOURCES.md), then run:

```text
python preprocessing/JUMP_Tox21_feasibility_2026-09-07_v1/run_metadata_overlap.py
python preprocessing/JUMP_Tox21_feasibility_2026-09-07_v1/run_profile_qc.py
python preprocessing/JUMP_Tox21_feasibility_2026-09-07_v1/run_second_task_benchmark.py
python preprocessing/JUMP_cell_count_proxy_intake_2026-09-08_v1/run_intake.py
python analysis/Cross_context_fair_increment_followup_2026-09-20_v1/run_jump_fair.py
```

The count-proxy intake retains the historical local filename `profiles_var_mad_int (1).parquet` and checks its exact size and SHA-256. Rename the downloaded count-containing file accordingly. JUMP batch-corrected public features were processed by their source authors; this is not a claim to have re-extracted image features inside our cross-validation.

### Cardiac precursor and explanatory analyses

```text
python analysis/A1_cross_cell_transfer_2026-09-06_v1/run_A1_benchmark.py
python analysis/A1_negative_transfer_and_candidate_scan_2026-09-06_v2/run_diagnostics_and_candidate_scan.py
python analysis/Remaining_evidence_closure_2026-09-20_v1/run_cardiac_reliability.py
```

The first two scripts generate `analysis_matrix.csv.gz`, `oof_predictions.csv.gz`, `full_cardiac_pathway_slopes.csv.gz` and `full_structure_oof_predictions.csv.gz`, among other diagnostic outputs. They are included because final analyses depend on them, not because all their exploratory candidate scans are primary manuscript claims. GSE262419, LINCS metadata/matrices, the compound supplement and the exact pathway library are required.

### EUOS final corrected analysis

```text
python preprocessing/EUOS_profiles_intake_2026-09-21_v1/intake.py
python preprocessing/EUOS_profiles_intake_2026-09-21_v1/prepare_profiles.py
python analysis/EUOS_locked_fusion_evaluation_2026-09-21_v2/correct_identity_closure.py
python analysis/EUOS_locked_fusion_evaluation_2026-09-21_v2/run_models.py selftest
python analysis/EUOS_locked_fusion_evaluation_2026-09-21_v2/run_models.py develop lr
python analysis/EUOS_locked_fusion_evaluation_2026-09-21_v2/run_models.py develop rf
python analysis/EUOS_locked_fusion_evaluation_2026-09-21_v2/run_models.py predict lr
python analysis/EUOS_locked_fusion_evaluation_2026-09-21_v2/run_models.py predict rf
python analysis/EUOS_locked_fusion_evaluation_2026-09-21_v2/score_locked.py
python analysis/EUOS_locked_fusion_evaluation_2026-09-21_v2/run_diagnostics.py
python analysis/EUOS_locked_fusion_evaluation_2026-09-21_v2/finish_uncertainty.py
python analysis/EUOS_locked_fusion_evaluation_2026-09-21_v2/run_simulations.py pilot
python analysis/EUOS_locked_fusion_evaluation_2026-09-21_v2/run_simulations.py formal
python analysis/EUOS_locked_fusion_evaluation_2026-09-21_v2/verify_run.py
```

Run diagnostics before `finish_uncertainty.py`: the latter reads single-well losses generated by the former. `verify_run.py` requires full-run artifacts, including newly generated locks, profiles and pilot simulations; it is not the quick-release smoke test.

EUOS development uses FMP-, IMTM- and MEDINA-HepG2; USC-HepG2 is the external laboratory. FMP-U2OS is a paired context stress test, not isolation of cell-line biology from acquisition conditions. Only SR-ARE and SR-MMP met the prespecified endpoint eligibility criteria. The corrected inventory contains 576 labeled parent compounds: 353 development, 145 strict holdout and 78 new-entity/seen-scaffold compounds. Endpoint-specific observed samples are smaller.

The seed for the principal split and fits is 20260921. Model families are logistic regression and a random-forest sensitivity analysis. S denotes structure, C count-derived features, M morphology, and B structure plus count. F is selected within training from early fusion or the probability mixture `(1-w) B + w M`; it is not a mixture of feature vectors. The scripts retain all comparisons, including null or unfavorable results.

**Identity correction:** v2 is a corrected reanalysis after v1 scores had been inspected. CEFOXITIN moved out of the strict new-scaffold pool when historical scaffold representations were closed across sources. No models, thresholds or final laboratory were changed. This must not be described as a new blinded validation. The historical v1 results remain in the authors' project archive and are not a second independent benchmark in this repository. The two original specification files are retained, in their original language, for provenance; their older sample counts are superseded by the explicit v2 correction and eligibility table.

Portable paths change code hashes. A raw-data rerun generates its own decision and prediction locks. Never edit historical hashes to make a new run appear to have been frozen before its outcomes were known.

The EveBio fairness script imports functions from the earlier scaffold-audit script. That helper reads the header of `CP_all_EveBio.csv` when imported, so the data file must already be present. ### OASIS

```text
python analysis/Remaining_evidence_closure_2026-09-20_v1/run_oasis_paired_pod.py
```

This reanalyzes five published point-of-departure result tables. It does not repeat the original image processing or dose-response fitting. Complete-case paired concentration ratios are not temporal ordering, target specificity, or clinical toxicity estimates.

## Figures and tables

After all required result CSVs are available:

```text
python figures/build_figures_v81.py
```

Outputs: four main and five supplementary figures in TIFF (600 dpi), PDF and SVG under `outputs/Figures/`; PNG previews, panel-level CSVs, legends, input hashes and a source-data ZIP under `outputs/figure_build/`. Arial is used when installed; font substitution can change layout on other systems. The publication TIFFs themselves are not versioned in this code repository.

[table_source_map.json](table_source_map.json) maps Table 1, Table 2 and Tables S1-S20 to the corresponding source CSVs. These are analysis-result tables, not copies of the final Word/Excel submission formatting. Blank/undefined values must not be converted to zero.

## Validation limits

See [VALIDATION.md](VALIDATION.md) for the checks actually performed for this release. Rebuilding figures or recomputing metrics from archived predictions is narrower than reproducing model fitting from raw data. These analyses support context-specific comparisons; neither two external endpoints nor supporting datasets establish a universal reliability guarantee.
